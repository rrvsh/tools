## Task

User requested exhaustive research of Hyprland workspace and window layout management options, explicitly using the Hyprland docs index skill and subagents.

## Approach

- Read `.agents/skills/hyprland-docs-index/SKILL.md` to identify official documentation endpoints.
- Spawned parallel subagents to keep context focused:
  - Workspace management surface (rules, dispatchers, binds, variables, hyprctl, IPC).
  - Window layout management surface (dwindle/master/layout knobs, dispatchers, rules).
  - Runtime automation surface (hyprctl + socket2 events and scripting caveats).
  - Plugin extension surface (capabilities, hyprpm workflows, caveats).
- Aggregated overlapping findings into one consolidated option map.

## Key Decisions

- Kept scope to official docs URLs from the index and directly linked pages needed for completeness (Dwindle/Master layout pages referenced by Variables).
- Organized output by practical decision axis:
  - Native config-time controls.
  - Runtime dispatch/automation controls.
  - Extension path via plugins.
- Included caveats/constraints that materially affect safe automation or expected behavior.

## Findings Snapshot

- Workspace management: rich controls across `workspace` rules, dispatcher target syntax (`+/-`, `m~`, `e~`, `previous`, `special`), monitor mapping, persistence, naming, special workspaces, and gesture/bind behavior.
- Layout management: global layout selection plus detailed knobs for dwindle and master, per-workspace layout/orientation policy, grouping/tabbing operations, floating/tiled/fullscreen state transitions, and runtime setprop/layoutmsg controls.
- Automation: `hyprctl` query/control + `--batch`, JSON output, socket2 event stream (`workspace*`, `moveworkspace*`, `openwindow`, `changefloatingmode`, `submap`, etc.), and synchronous-call caveats.
- Plugins: intended for behavior beyond native config; documented install/management via `hyprpm` with security and version-compatibility caveats.

## Issues / Caveats Encountered

- Some layout-specific options are not fully expanded on the generic Variables page and require reading dedicated Dwindle/Master layout docs for exhaustive coverage.
- Several dispatcher behaviors include constraints (e.g., `special` target support limited to specific dispatchers) that are easy to misuse in scripts.

## Learning Points

- Hyprland exposes almost all workspace/layout control along a clean spectrum: static rules -> dispatcher calls -> event-driven IPC automation -> plugin-level extension.
- Robust automation should be event-driven via socket2 with batched control calls, not tight polling loops.
