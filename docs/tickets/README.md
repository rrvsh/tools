# Ticket RULES:

- Copy `docs/tickets/0-template.md` and fill it out; keep the section headers unchanged.
- Title: conventional commit style, mention platform/scope (e.g., `feat(macOS): manage hidden folders`).
- “What issue is this solving?”: a 1–3 sentence problem statement with desired end state; avoid solutions here.
- “Code”: describe the final shape in the repo—files touched, options, algorithms, validation—so an implementer can proceed without guessing.
- “Workflow”: explain how a user runs/uses the feature and how it fits with existing tools (`just`, `nix develop`, activation scripts, etc.).
- Keep it concise; no TODOs or open questions—tickets should be ready to implement.***
